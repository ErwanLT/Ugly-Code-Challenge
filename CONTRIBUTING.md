# CONTRIBUTING — Participer au concours

## 1. Préparer sa participation

Forkez le dépôt et créez une branche dédiée à votre participation.

Votre réalisation doit être placée dans :

`editions/<année>/<édition>/candidates/<identifiant>/`

Exemple :

`editions/2027/2027-01-ministere-des-excuses/candidates/erwan/`

## 2. Structure du projet

Vous êtes totalement libres de l'organisation interne de votre projet.

En revanche, votre dossier doit contenir un README.md présentant :

- Votre nom ou pseudonyme.
- Le langage et les technologies utilisés.
- Une description de votre solution.
- Les instructions d'installation.
- Les instructions d'exécution.
- Les instructions de test.
- Une capture d'écran ou une démonstration si pertinente.

## 3. Règles de participation

- Une seule Pull Request par candidat et par édition.
- Une seule réalisation par candidat.
- Ne modifiez pas les fichiers des autres candidats.
- Ne soumettez pas de code malveillant.
- Ne commitez pas de secrets, tokens ou données personnelles.
- Votre réalisation doit être exécutable et démontrable.
- Les changements après la clôture des soumissions ne sont pas autorisés.

## 4. Présentation

Chaque candidat doit pouvoir présenter sa réalisation en quelques minutes.

Montrez-nous :
- Ce que fait votre programme.
- Comment le lancer.
- Pourquoi votre code est une aberration.
- Pourquoi vous estimez mériter la victoire.

## 5. Vote

Le vote s'effectue directement sur les Pull Requests.

Une réaction 👍 compte comme un vote.

La Pull Request ayant obtenu le plus de réactions 👍 à la date de clôture remporte l'édition.

## 6. Dernier conseil

Ne cherchez pas à impressionner avec une architecture propre.

Cherchez à nous faire dire :

« Mais pourquoi ?! »

Et surtout, faites en sorte que ça fonctionne.
